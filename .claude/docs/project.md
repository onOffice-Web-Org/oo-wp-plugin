# Project overview

Part of the oo-wp-plugin working instructions — index: [../../CLAUDE.md](../../CLAUDE.md).

## What oo-wp-plugin is

**onOffice for WP-Websites** — the WordPress plugin that pulls real estates, addresses and contact
forms from the onOffice enterprise API and renders them into any WordPress theme via shortcodes.

There is **no FTP sync and no local mirror of the estate data.** Every frontend request goes through
the onOffice API (cached in `DBCache`, TTL 3600). That single fact drives most performance findings
in a review — a loop over estates that calls the API per row is a real bug here, not a theoretical
one.

| | |
| --- | --- |
| PHP | `>= 8.2` (composer `platform.php = 8.2`) |
| WordPress | requires `6.1`, tested up to `6.9.1` |
| Text domain | `onoffice-for-wp-websites`, `Domain Path: /languages` |
| License | plugin AGPL-3.0; `config/` and `templates.dist/` GPL-3.0 |
| Shortcodes | `[oo_estate]` `[oo_address]` `[oo_form]` `[oo_basicdata]` `[oo_link]` |
| Own DB tables | 21 `oo_plugin_*` tables behind `$wpdb->prefix`, see [database-and-migrations.md](database-and-migrations.md) |
| Updates | self-hosted via `oo-updater.php` against `onoffice-wp-updates.de` — **not** wordpress.org |

Unlike the four theme repos, **this repo has a real test suite** (319 test files, PHPUnit against
the WordPress test suite). Tests are therefore a review gate here, not advisory — see
[testing.md](testing.md).

## What belongs where

| Path | Owns |
| --- | --- |
| `plugin/` | all plugin code, `onOffice\WPlugin\` (449 files, 25 namespaces) |
| `plugin.php` | constants, the DI container, **every** `add_action`/`add_filter` registration |
| `config/di-config.php` | PHP-DI bindings: interface → implementation, scalars, `wpdb` |
| `SDK/` | `onOffice\SDK\` — mirror of an upstream repo, see below |
| `templates.dist/` | the default output templates — **a public API**, customers copy them out |
| `js/` → `dist/` | source JS → minified by terser; `dist/` is generated, never committed |
| `css/`, `third_party/` | stylesheets and vendored JS/CSS assets (leaflet, altcha, tom-select, accessible-slick) |
| `languages/` | POEditor-owned, only `-de_DE.po` is hand-edited — see [documentation/TRANSLATIONS.md](../../documentation/TRANSLATIONS.md) |
| `vendor-prefixed/` | generated by Strauss, see [architecture.md](architecture.md#prefixed-dependencies-strauss) |

**Rule of thumb:** data access belongs in a `Record/RecordManager*`, API access behind
`SDKWrapper`/an `APIClientAction`, WordPress globals behind a `WP/` wrapper. Those three seams are
what makes this codebase testable — code that reaches around them is the most common architectural
finding.

## Related repositories

This plugin is part of a six-repo family under the `onOffice-Web-Org` owner. `pr-preview.yml` is
byte-identical in all six and dispatches across them, keyed on branches tagged `P#<number>`.

```
                     oo-wp-plugin  (this repo — estate/address/form data + shortcodes)
                            │  consumed by
      ┌──────────────┬──────┴───────┬──────────────────┬──────────────┐
onoffice-classic  onoffice-modern  onoffice-pure  onoffice-timeless   oo-vue-addons
      └──────────────┴──────┬───────┴──────────────────┘
                     onoffice-shared   (git submodule "shared" in all four themes)
```

| Repo | Relation |
| --- | --- |
| `onoffice-classic`, `onoffice-modern`, `onoffice-pure`, `onoffice-timeless` | The four parent themes. Each carries an `onoffice-theme/templates/` directory (incl. `fields.php`) that calls `onOffice\WPlugin\*` classes **directly**. A renamed public class, method or template variable breaks them silently. Note their `fields.php` files are *not* copies of each other — a signature that exists in one may differ in another. |
| `onoffice-shared` | The themes' shared submodule. Does not call this plugin directly, but its blocks render the markup around this plugin's output. |
| `oo-vue-addons` | Frontend add-ons consuming the same data; several theme blocks are gated on `is_plugin_active('oo-vue-addons/…')`. |
| `onOfficeGmbH/sdk` | **Upstream of `SDK/`.** `SDK/src/internal/ApiCall.php` intentionally diverges: it imports phpgeo under the *prefixed* name, which upstream does not. A re-sync from upstream silently reverts that; `composer check-prefixed-imports` turns it into a failing build instead of a broken radius search. |

### When you need another repository

The trigger is the `P#<number>` tag in the branch name or PR title: if a branch with the same tag
exists in a sibling repo, the change is one cross-repo ticket and the sibling side matters.

Check a theme repo when the change touches:

- **shortcode output or template variables** — the variables `Template::getIncludeContents()`
  exposes (`$pEstates`, `$pForm`, `$pAddressList`, `$generateSortDropDown`, `$getListName`,
  `$scriptLoader`), or the markup in `templates.dist/`,
- **CSS class names or script handles** — the themes style this plugin's output and enqueue against
  its handles (`ScriptLoader/ScriptLoaderGenericConfigurationDefault.php`),
- **any public `onOffice\WPlugin\*` class, method or constant** that a theme's
  `onoffice-theme/templates/` could call,
- **`field-dependencies.json`** or field-name constants the themes mirror.

Check `oo-vue-addons` when a shortcode/block data contract changes; check `onOfficeGmbH/sdk` when
touching `SDK/`.

How to get access: the review workflow's cross-repo token step (see [workflow.md](workflow.md))
requests read on the sibling repos via the `OO_ACTIONS_BOT` GitHub App. Locally there is **no `gh`
CLI and no sibling checkout in CI** — if it isn't available, say what couldn't be checked rather
than guessing.
